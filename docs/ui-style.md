status: Confirmed

适用平台：PC 桌面浏览器。设计基准视口 1440×900。可用宽度从 1280px 起；更窄时整页横向滚动，不做移动端重排。

依据：`docs/PRD.md` 的 REQ-001～REQ-018、AC-001～AC-104，以及已确认的 `docs/tech-spec.md`。登录页显示密码沿用现有认证卡片，不另起一套视觉。

2026-10-04 用户正式确认 1.0 原型：`docs/prototypes/index.html` 及同目录样式、脚本与素材。下文里「确认前保持 Draft」的句子是确认前的检查记录。确认后，前端实现以本文件和该原型为准，必须 100% 还原原型中的全部样式和交互。

本次界面：登录、注册、找回密码、创建婚礼项目、婚礼档案、备婚计划书、预算管理本、婚宴座位表、新建对话。可操作原型：`docs/prototypes/index.html`。对话页沿用已确认的浅灰侧栏、白内容区、玫瑰粉和像素字，不另起一套对话皮肤。

## 一、设计目标与风格判断

### 产品类型与体验目标

这是给准新人自己用的备婚工作台，不是婚礼邀请函或营销页。用户最常做的是看下一步任务、改任务状态、分配预算、把宾客拖进桌子。信息以名单、金额和日期为主，密度中等，一次会停留较久。

体验目标：打开就能看见倒计时、进度和今天要做的事。界面像一份可以点进去改的文档，颜色只负责指出当前操作和状态。

### 视觉风格

交互仍接近 Notion：任务行不套卡片，悬停整行出现浅色底，当前模块用底色加文字色标出。2026-10-02 用户要求左侧分栏用浅灰，点缀保持婚礼和爱情主题的粉红色。黑色侧栏不再使用。

建议并已落到原型的配色：

- 右侧页面为纯白。左侧分栏为浅灰 `#F7F7F5`，右边有一条淡分隔线。当前模块用浅玫瑰底，文字用玫瑰粉 `#D43774`。四个模块名未选中时用暖近黑 `#37352F`。侧栏其余次文字为暖褐。
- 全产品只用一种鲜明强调色：玫瑰粉 `#D43774`。它用于主按钮、链接、焦点、进度、今日待办左边线、当前导航和主桌边框。悬停主按钮变为 `#B82A64`。
- 正文用暖近黑 `#37352F`，辅助字用暖褐 `#8A756E`。认证页外底、分类详情、未排座池和桌把手与侧栏同为浅灰 `#F7F7F5`。
- 任务状态在行首直接改。未开始是灰底深字；进行中是天蓝底白字；已完成是深绿底白字；已超期是正红 `#FF0000` 底白字。预算状态仍是前三套：未确定灰底灰字，已支付天蓝底白字，已确定深绿底白字。出席仍是浅底深字。超分是玫红，满桌和逾期是香槟暖杏。颜色上写中文。
- 宾客分组和预算扇区在玫瑰、梅子紫、鼠尾草和香槟之间区分，避免再出现蓝色。
- 不铺金箔、不铺花卉底纹、不用书法标题。文字用像素体，不用无衬线界面字。动效只服务拖拽高亮。
- 产品标志是一枚马赛克爱心：8×7 个方块拼出心形。每块 4px，块与块之间的缝为 1px，全部使用 Accent `#D43774`。标志放在「备备」左侧，间距 8px。登录卡片为 39×34px。功能页侧栏同一枚图形缩小三分之一，为 26×22.67px。注册、找回密码和建项不放这枚标志。

已确认的产品约束：只做 PC、简体中文、左侧三个模块、计划书为默认页。2026-10-02 用户确认全站改用像素字体，字号按下面的字阶。配色按本节，间距仍是已落到原型的方案。

### 关键 UX 规则

1. 每个页面只有一个主按钮，使用 Primary。取消、返回、删除用次按钮或文字按钮。删除桌位、退出登录先保持可见结果，不用只弹一句说明代替结果。
2. 校验失败时，字段下用错误色短句说明原因，已填写的内容保留。
3. 列表和画布在右侧内容区滚动。内容区始终留出竖向滚动条的位置，列表变长时宽度不变。顶栏统计、侧栏和表单主按钮不跟着长列表滚出可视区域；座位画布自己滚动和缩放，页顶统计条固定在内容区顶部。同一页面内的操作重画后，内容区、左侧名单和全部宾客名单保持滚动位置。切换模块或进入另一页时从顶部开始。
4. 等待时主按钮变为「正在保存」并禁用，避免重复提交。请求失败时恢复按钮，并在操作附近显示失败原因。
5. 拖拽入座先移动芯片；请求失败时芯片回到拖拽前的位置，并显示失败原因。满桌时桌卡片出现橙色「已满，仍可入座」，不阻止放下。
6. 地址与导航一致：刷新后仍停在当前模块，侧栏高亮与内容相同。未登录不能打开三个模块。已登录但没有婚礼项目时，只能停留在创建婚礼项目。

### 字体与字阶

中文、英文和数字使用同一套像素字体：`"Fusion Pixel 12px Prop zh_hans", "Microsoft YaHei", sans-serif`。原型文件是 `docs/prototypes/fonts/fusion-pixel-12px-proportional-zh_hans.otf.woff2`（Fusion Pixel 12px 简体比例体，2026.09.01）。授权为 SIL Open Font License 1.1，许可证在同目录 `OFL.txt` 与 `LICENSES/`。缺字时回退微软雅黑。这套字只有字重 400，关闭字体合成和字体平滑，字距为 0。不使用等宽数字特性，数字宽度以该像素字为准。

像素格子在 12px 及其整数倍上最清晰。正文、区块标题和按钮用 12px，页面标题和关键数字用 24px。计划书的婚礼日期和倒计时天数、预算总预算、座位表宾客总数用同一套 36px Accent，并向右叠 3px 同色阴影。婚礼日期与倒计时同一套排版：12px 辅助色标签在上，36px 数字在下。日期写成「年/月/日」，月和日不补零。同一展板里已完成、进行中仍是 24px Ink。天数旁边的「天」仍是墨色，不进入这套强调。2026-10-02 用户指定例外：侧栏产品名 20px、字重 700，备婚计划书五个阶段标题 16px，任务标题和预算名称 14px、字重 700。2026-10-03 用户指定：阶段序号标签 12px、字重 700。2026-10-03 用户指定：计划书温馨提示 14px、字重 400、Accent。预算本同一位置用同一套，文案为「* 温馨提示：点击长按拖动可调换预算位置哦~」。2026-10-03 用户指定：侧栏四个模块名 14px。同日再指定：未选中字重 400、暖近黑 `#37352F`；选中字重 700、玫瑰粉。登录页产品名「备备」在卡片内水平居中，28px、字重 700。这套像素字没有 700 字重，功能页侧栏和登录页的「备备」，侧栏当前模块名，计划书任务标题、预算名称，以及阶段序号标签，允许合成字重。未选中的模块名不合成字重。PC 不随宽度缩小字号。系统显示缩放不是 100% 时，点阵仍可能被操作系统平滑。

### 布局、间距与形状

- 功能页外壳：左侧栏展开时宽 232px、高 100vh、位置固定。右上角折叠标志是白底圆角方框。展开时深色竖条在左侧，收起后竖条移到右侧。折叠后侧栏宽 44px，显示产品标志、四个模块标志、折叠按钮，以及底部三枚图标：设置、编辑婚礼档案、退出登录。不显示历史、「编辑婚礼档案」和「退出登录」的文字，也不显示个人中心的头像、用户名和日期。这三枚图标与展开态设置标记同一套：32px 白底、无边框、圆角 10px、20px 描边图形、深灰 `#666666`；鼠标放上去时底变成浅粉 `#FDE7F0`，图形变成 Accent `#D43774`。宽度用 520ms 缓出过渡，文字和底部一块同时淡出，这三枚图标同时淡入，折叠按钮和产品标志在同一段里移到上下排列，收尾不再改布局。右侧内容区占剩余宽度并跟着变宽，自身滚动，上右下左内边距 32px。再点展开后文字按钮淡回来，底部三枚图标淡出。档案抽屉滑入滑出同样缓出，大约 560ms。切换模块后折叠状态保持。
- 认证页与建项页没有侧栏。卡片宽 420px，在视口中水平垂直居中。建项卡片宽 560px。登录和注册的页面背景是浅灰 `#F7F7F5`，上面只重复马赛克桃心，文件为 `docs/prototypes/auth-hearts.svg`。没有灰白方块。桃心是产品标志那套 8×7，每块 5px、缝 1px，颜色 Accent `#D43774`。左右和上下各留 3 格，重复单元是 84×78px。桃心本身仍是每块 5px。卡片仍是白底。找回密码和建项不用这张背景。
- 间距刻度：4、8、12、16、24、32px。卡片内边距 24px，卡片之间 16px。
- 输入框高 34px，按钮高 32px，圆角 4px。登录卡片圆角 8px。宾客芯片高 24px，圆角 4px。导航项高 44px，圆角 8px，与「最近」里当前对话和悬停行相同。退出登录是白底描边按钮，高 36px，文字居中。
- 主内容最大阅读宽度不限，预算和计划在 1440 视口下铺满内容区。座位画布高度为视口高度减去页顶统计条约 88px，画布内部再缩放和平移。
- 窄于 1280px：不改变侧栏和分栏，浏览器出现横向滚动。

### 层次、阴影与动效

右侧页面是白色。任务和分类靠悬停浅灰区分，不给每一行套边框。左侧分栏是浅灰，右边有一条 Divider。拖拽中的芯片或桌卡片使用轻微阴影。经过目标桌时，桌卡片边框立即变为 Accent。保存成功不弹动画。系统开启「减少动效」时，去掉阴影，拖拽结果仍然立即呈现。

- **内容呈现**：字段纵向排列，间距 16px。错误句在密码框下，最多两行。
- **组件清单**：

- **布局结构**：与登录同一张居中卡片，背景同样是整齐排列的马赛克桃心。顺序：用户名、密码、手机号、注册。链回登录。

### UI-03 找回密码

- **依据与目标**：用绑定手机号重置密码。验证码不出现在页面上。
- **布局结构**：居中卡片。顺序：手机号、获取验证码、验证码、新密码、重置密码。
- **内容呈现**：「获取验证码」是次按钮，在手机号同一行右侧。发送后按钮变为「60 秒后可重发」并禁用，这只是防止连点，不代表短信一定送达。
- **组件清单**：手机号、验证码、新密码、次按钮「获取验证码」、主按钮「重置密码」。
- **状态与操作结果**：发送失败 → 手机号下显示「验证码暂时无法发送，请稍后再试」，不显示验证码。验证码错误或新密码不合规 → 停在本页，密码不变。成功 → 提示「密码已更新，请用新密码登录」并进入 UI-01，不自动登录。
- **示例数据与文案**：手机号「13800010001」，仅供演示。
- **页面例外**：获取验证码与输入同一行，是全局「一页一个主按钮」下的次操作，主按钮仍是重置密码。

### UI-05 婚礼档案

- **依据与目标**：在当前模块上修改已有档案，并展示用户自己上传的新人合影或婚纱照。侧栏「编辑婚礼档案」从内容区右侧向左抽出抽屉，不离开来源页。从预算页进入时，总预算字段聚焦。关联 AC-011、AC-041、AC-090～AC-096。原型：[prototypes/index.html#/wedding?from=plan](prototypes/index.html#/wedding?from=plan)。
- **布局结构**：抽屉盖住内容区，不盖住侧栏。侧栏高亮仍是打开前的模块。抽屉内标题是「婚礼档案」。同一行右上方是次按钮「返回」，与标题垂直居中。其下左右两栏等高，各有 1px Line 边。左栏没有栏标题，底色与侧栏相同，输入框仍是白底。最上方第一排是新郎昵称和新郎生日，第二排是新娘昵称和新娘生日，生日用日历选择。其下是开始备婚日期等五个字段，最下方是「其他婚礼偏好」，输入框预留四行。整份档案留在一屏内，左栏不出现滚动条。主按钮「保存」在栏内右下角，距右缘和下缘各留出栏内边距。右栏标题「上传婚纱照/新人合照」居中，14px、暖近黑。两栏下边框与侧栏「退出登录」的下缘齐平。没有照片时，右栏边框为宽 3、高 4，底色与侧栏相同，「上传照片」在标题下方的区域里水平并垂直居中。有照片时，这一张撑满整个右栏，超出部分裁切，不再显示「上传婚纱照/新人合照」。鼠标移到合影上，正中才出现次按钮「更换合影」，白底 50% 透明、无边框、暖近黑字。鼠标再碰到这个按钮时，变成 Accent 粉底、白字。离开按钮后回到半透明白底。离开合影后按钮消失。侧栏「编辑婚礼档案」最右侧有白色实心小三角，收起时向左，抽出时向右。点一次抽出，再点一次收回，三角跟着翻转。抽出和收回都用 480ms，慢起、中段均匀、慢收，位移落在整设备像素上。系统要求减少动效时直接出现或消失。窄于 1280px 时两栏仍并排，整页横向滚动。
- **内容呈现**：左栏第一排是新郎昵称和新郎生日，第二排是新娘昵称和新娘生日，生日用日历选择，可以留空。其下五个字段与建项相同。最下方是「其他婚礼偏好」，输入框高 96px，可放下四行 20px 文字，可以留空。文字再多时只在框内滚动。从预算进入时，总预算字段处于聚焦。右栏没有照片时，只在栏内放次按钮「上传照片」，不放示例图。有照片时只显示这一张，铺满右栏。鼠标没有放在合影上时不显示「更换合影」。
- **组件清单**：标题行次按钮「返回」。左栏九个输入、主按钮「保存」。右栏次按钮「上传照片」，以及每张的「更换」「删除」。页面只有一个主按钮。创建页仍是五个输入。
- **状态与操作结果**：选中合格图片后立刻出现，不必点「保存」。格式不符时右栏写「请上传 JPEG、PNG、GIF 或 WebP 图片。」超过 5MB 时写「这张照片超过 5MB，请压缩后再上传。」已有 1 张时不再出现「上传照片」。这些失败都不换掉已有照片，五个字段保持不变。鼠标移到合影上，正中出现「更换合影」；移开后消失。点它并选合格图片后，只替换这一张，仍撑满右栏。保存五个字段成功 → 回到来源页。改了总预算 → 预算页合计按新总额重算，分类金额不变。改了婚礼日 → 倒计时和当前阶段按新日期；没手改过截止日期的任务重算，手改过的保持原值。改了总人数 → 座位表宾客总数不变。保存失败 → 留在本页并保留输入。点「返回」、再点一次侧栏「编辑婚礼档案」，或保存后再进入，已上传的照片仍在。计划书、预算本、座位表和 XiaoBei 不显示这些照片。
- **示例数据与文案**：把婚礼日从 2027-10-20 改为 2027-11-20。右栏可以没有照片。
- **页面例外**：侧栏高亮保持来源模块。栏标题 14px。创建婚礼项目页不加右栏，也不是抽屉。

## 五、使用与验收

应采用：侧栏只标当前模块；主按钮全页只有一个；状态同时有颜色和中文；金额两位小数；超分和满桌用 Danger 或 Warning 文字，不拦截保存或入座。

应避免：金红喜帖底纹、书法大标题、无衬线界面字、字阶表以外的非 12 倍数的字号和合成粗体、负字距、移动端汉堡菜单、长按选桌、把验证码显示在页面上、用弹窗代替入座或删桌后的列表变化。

文档检查：UI-01～UI-08 都有布局、组件、状态和示例，范围停在已确认需求内。色值和字号只在全局表定义，页面引用名称。主按钮、错误保留输入、长文本换行或省略已写明。适配方式是 1280px 以下横向滚动。
